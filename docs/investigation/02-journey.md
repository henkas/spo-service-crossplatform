# Approaches tried before the real fix

Short log of the intermediate workarounds that preceded the real fix in
[`03-real-fix.md`](03-real-fix.md). Each exposed part of the problem
without solving it fully. They are kept here so the conclusions can be
reproduced independently, not because they are recommended paths.

## Environment

- PowerShell 7.5.4
- macOS Darwin 25.2.0, arm64
- `Microsoft.Online.SharePoint.PowerShell` 16.0.27111.12000
- `PnP.PowerShell` 3.1.0

## 1. Reflection-based `Connect-SPOService` bypass

Script: [`artifacts/Connect-SPOServiceMacWorkaround.ps1`](artifacts/Connect-SPOServiceMacWorkaround.ps1).

Builds `CmdLetContext` and `SPOService` directly via reflection, skipping
`SPOServiceHelper.InstantiateSPOService` and its null-deref on registry
roots (see [`01-root-cause.md`](./01-root-cause.md)).

- Got the module past the immediate `NullReferenceException`.
- Both interactive and certificate auth paths then failed with
  `400 Bad Request` from SharePoint. At the time, the cause looked like a
  server-side auth / routing issue.
- Verdict: useful for isolating defect #1; not a usable workaround by
  itself. The actual cause of the 400 turned out to be defect #2 in the
  HTTP pipeline — see [`03-real-fix.md`](03-real-fix.md).

## 2. `PnP.PowerShell` auth bridge

Script: [`artifacts/Connect-PnPSPOWorkaround.ps1`](artifacts/Connect-PnPSPOWorkaround.ps1).

`Connect-PnPOnline` with the same certificate works on macOS because PnP
ships a newer `Microsoft.SharePoint.Client.Runtime` (16.1.x) whose
`HttpWebRequestExecutor` does not have defect #2. That made PnP a
reliable way to drive CSOM during the investigation, even while the SPO
module's own pipeline was broken.

- Works for generic tenant CSOM via `Get-PnPContext`.
- Does not expose the SPO module's cmdlets; is not a drop-in replacement.

## 3. Org Assets workaround pack

Script: [`artifacts/SPOOrgAssetsMacWorkaround.ps1`](artifacts/SPOOrgAssetsMacWorkaround.ps1).

Reimplements `Get-`, `Add-`, and `Remove-SPOOrgAssetsLibrary` on top of
the PnP `ClientContext`, calling the underlying Tenant CSOM methods
(`GetOrgAssets`, `AddToOrgAssetsLibWithConfig`, `RemoveFromOrgAssets`)
directly.

Notable service-side quirk confirmed here:
`Tenant.RemoveFromOrgAssets` accepts exactly one identifier at a time —
either `(libraryUrl, Guid.Empty)` or `(string.Empty, listId)`, never both.

- Works end-to-end against a real tenant.
- Still tied to PnP; does not get you the official `Remove-SPOOrgAssetsLibrary`
  cmdlet itself.

## 4. Brand Center deactivation via direct `ProcessQuery`

Script: [`artifacts/Invoke-SPOBrandCenterDeactivation.ps1`](artifacts/Invoke-SPOBrandCenterDeactivation.ps1).

The Brand Center path could not be handled through the PnP-loaded CSOM
assembly because `PnP.PowerShell` loads
`Microsoft.Online.SharePoint.Client.Tenant` 16.1.0.0, whose `Tenant` type
does not expose `DeactivateBrandCenterFeatures()`. The SPO module ships
the 16.0.0.0 version, which does.

The helper:

1. Spawns a clean `pwsh -NoProfile` process.
2. Loads only the SPO module assemblies (so `Tenant` 16.0.0.0 resolves).
3. Acquires an app-only token via MSAL with the local certificate.
4. Gets a form digest from `/_api/contextinfo`.
5. Calls `tenant.DeactivateBrandCenterFeatures()` to populate the pending
   request, extracts the CSOM body via reflection on
   `ClientRequest.SetupQuery()`, and POSTs it to
   `/_vti_bin/client.svc/ProcessQuery` directly with `Invoke-WebRequest`.

This worked because it bypassed the runtime's HTTP pipeline entirely.
That was also the strongest hint pointing at defect #2: the body
generated by the runtime was valid, but the runtime's own POST of that
same body was not.

Idempotent in practice:

- If Brand Center is active, the CSOM call deactivates it and returns
  success.
- If already inactive, the server returns an `InvalidOperationException`
  with `"No active Brand Center features found"`, which the helper
  translates into `{ Success = true, AlreadyInactive = true }`.

## Why all four are now superseded

With the `HttpClient`-based shim in place (see
[`03-real-fix.md`](03-real-fix.md)), the official SPO cmdlets run against
the repaired pipeline directly:

- `Remove-SPOOrgAssetsLibrary -LibraryUrl …` replaces the org-assets pack.
- `Tenant.DeactivateBrandCenterFeatures()` through a normal
  `ClientContext.ExecuteQuery()` replaces the direct `ProcessQuery`
  helper.
- The reflection bypass and the PnP bridge are no longer needed.

The scripts are kept under [`artifacts/`](artifacts/) as evidence, not as
recommended usage.
